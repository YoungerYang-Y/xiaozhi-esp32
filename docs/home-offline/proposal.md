# 家用变体：BOOT 交互与离线模式方案

日期：2026-11-27。状态：交互与能力范围已确认，本文整理设计共识，尚未实施或进行设备验收。

适用范围：Waveshare ESP32-S3-Touch-LCD-1.85C Rev2.0，
`config.home.json` / `CONFIG_WAVESHARE_1_85C_HOME` 家用变体。
普通板型和其他板卡的默认行为不随本方案改变。本方案不指定新的发布版本。

## 1. 目标与现状

目标：网络不可用时设备仍能进入可操作的待机界面，通过本地唤醒和固定指令控制设备；
支持主动选择并跨重启保留离线模式，同时修正在线聆听无法用 BOOT 再次单击取消的问题。

本地代码检查得到的现状：

- 已保存 Wi-Fi 时，启动连接超时为 60 秒，超时后进入配网；无配置时直接进入配网。
- 配网状态下单击 BOOT 在配网与音频测试之间切换，没有退出到离线待机的入口。
- 家用 BOOT 单击处理覆盖待机、回答等状态，尚未处理聆听中再次单击取消。
- 已有本地音量、亮度、背光和电池状态接口，但云端工具调用不能代替离线指令入口。
- 小妹妹独立资源使用中文 MultiNet 模型，目前只注册“你好小妹妹”，且只处理唤醒动作。
  配网状态关闭唤醒检测，应用现有唤醒流程还依赖协议实例。
- 因此，退出配网、增加离线状态或仅修改命令词资源，均不足以单独实现本方案。

现有说明见[家用板卡说明](../../main/boards/waveshare/esp32-s3-touch-lcd-1.85c/README.md)
及[小妹妹资源说明](../../main/boards/waveshare/esp32-s3-touch-lcd-1.85c/assets/home-girl/README.md)。

## 2. 模式与恢复原则

采用“自动降级＋手动离线”。两种离线状态共用固定指令和本地界面，联网策略不同。

| 模式 | 联网策略 | 恢复方式 | 跨重启行为 |
| --- | --- | --- | --- |
| 在线使用 | 使用现有云端对话流程 | 连接失败时提供本地降级能力 | 启动时重新判断连接情况 |
| 自动降级 | 本地功能可用，后台重试 Wi-Fi 或服务故障阶段 | 满足第 3 节的在线待机条件后自动上线 | 不持久化本次故障状态 |
| 手动离线 | 结束云端会话、停止音频上传、关闭 Wi-Fi，不自动重连 | 用户选择恢复联网或主动进入配网 | 保存离线选择，重启仍离线 |
| 配网 | 显式提供网络配置入口，不开展云端或本地语音会话 | 配置成功后尝试联网，或单击 BOOT 退出 | 退出且无网络时保存为手动离线 |

联网模式与“监听暂停”“屏幕息屏”相互独立。界面应能表达“离线且监听暂停”等组合，
不能用切换模式的方式隐式解除暂停或强制亮屏。

用户选择“恢复联网”表示撤销手动离线选择并尝试联网；连接失败后进入自动降级，
继续后台重试。主动进入配网也表示允许用户发起的联网流程；退出且仍无网络时重新保存手动离线。
保留原 Wi-Fi 凭据，只有用户提交新的网络配置时按现有配置流程更新。

## 3. 进入与退出流程

| 场景 | 目标行为 |
| --- | --- |
| 启动时已保存手动离线选择 | 直接初始化本地能力，不启动 Wi-Fi、配置拉取、激活或云端音频连接 |
| 启动时允许联网且已有 Wi-Fi 配置 | 从本轮首次连接尝试开始，前台等待目标上限为 15 秒；尚不可用时先进入离线待机，后台继续恢复 |
| 首次启动且无 Wi-Fi 配置 | 进入配网，提示“单击 BOOT 离线使用”；跳过后保存手动离线选择 |
| 在线运行中 Wi-Fi 断开 | 结束当前云端会话，进入自动降级；保留配置，后台重连 |
| Wi-Fi 正常但云服务不可用 | 提供本地降级能力，仅恢复相应服务阶段，不自动进入配网 |
| 自动降级后恢复连接 | 等当前本地指令窗口、反馈或菜单结束后恢复在线待机，不自动开始收音或续接旧会话 |
| 用户选择离线使用／保持离线 | 结束云端会话并关闭 Wi-Fi，保存手动离线选择 |
| 用户选择恢复联网／立即重试 | 立即发起一次相应连接尝试；失败时本地能力仍可用 |
| 配网中单击 BOOT | 停止配网；无网络时进入并保存手动离线，不进入音频测试 |

15 秒是本轮连接的前台等待预算，不代表包含全部硬件及模型初始化的开机总时长，
也不能作为终止驱动调用的保证。后台重试采用递增间隔，上限为每 5 分钟一次，
避免反复弹出配网、重复播放故障声音或持续阻塞本地操作；手动重试立即执行。

### 3.1 恢复在线待机与媒体验证

区分“允许重新发起在线对话”和“媒体已验证正常”。恢复在线待机不等待实际语音往返，
不直接使用现有包含 Media 阶段的 `service_state=available` 作为恢复门槛。

共同前提：当前 Wi-Fi 已连接、配置有效、激活已完成；本轮恢复没有新的失败或取消，
且用户仍允许联网。随后按协议取得以下证据：

| 协议 | 恢复在线待机的证据 | 媒体验证 |
| --- | --- | --- |
| WebSocket | 本轮建立连接并收到合法的服务端 hello | 保持未知，待用户主动发起对话后的识别与回复解码验证 |
| MQTT/UDP，未协商探测 | 本轮 MQTT 控制连接成功，且收到合法的会话 hello | 保持未知，待用户主动发起对话后的识别与回复解码验证 |
| MQTT/UDP，已协商探测 | 控制连接与会话 hello 成功，并收到本轮通道有效 PONG | PONG 可证明媒体路径可达，不等于整条 ASR／回答链路已验证 |

恢复探测只使用控制消息与已协商的探测包，不发送 listen/start、唤醒音频或麦克风音频，
不接纳探测会话的语音播放、通知或设备控制请求。现有建连成功回调不能直接把探测带入聆听。
本轮取得证据后正常关闭临时会话，必要的 MQTT 控制连接可保留；正常关闭不视为恢复失败。
只有用户下一次主动单击或唤醒才建立实际对话通道并开始收音。

后台探测可在本地使用期间运行，但切回在线待机须等待当前本地窗口、反馈或菜单结束。
探测证据与本轮恢复、网络及配置关联：断网、配置变化、手动离线或新的连接失败使其失效，
迟到的成功事件不能覆盖这些变化。历史媒体失败不阻止一次新的恢复尝试；
未验证的媒体状态保留为未知，不把恢复在线待机显示为“语音链路已验证正常”。
下一次实际会话失败时再次自动降级，沿用递增重试策略，避免持续切换模式。

## 4. BOOT、触控与网络菜单

### 4.1 BOOT 单击

| 状态 | 单击行为 |
| --- | --- |
| 在线待机 | 开始云端聆听 |
| 在线聆听 | 取消本次聆听、结束当前会话，回到待机，仍可再次单击或语音唤醒 |
| 在线回答中 | 沿用家用交互：打断回答并开始新会话 |
| 离线待机 | 开启本地固定指令窗口 |
| 本地指令识别中 | 取消本次识别，回到离线待机 |
| 配网中 | 退出配网，按第 3 节规则进入离线待机 |
| 监听已暂停 | 不启动收音；提示须双击恢复监听 |

“取消聆听”不是“暂停监听”：取消只结束当前一次交互；暂停关闭持续唤醒与指令识别。
待连接请求也须可被取消，不能在取消后因延迟完成的建连回调重新进入聆听。

### 4.2 BOOT 双击与长按

- 双击：结束当前交互并暂停监听，再次双击恢复到对应模式的可唤醒待机。
- 暂停时唤醒与指令识别均停止；语音不能用于恢复监听，必须通过 BOOT 双击恢复。
- 运行时长按 3 秒：亮屏打开网络菜单；长按不得额外触发单击或双击动作。
- 保留启动时 BOOT 对下载模式的硬件作用，不改动启动引脚行为。
- 升级写入等不能中断的阶段沿用现有操作保护，不强制切换网络或中止写入。

### 4.3 网络菜单

| 当前模式 | 菜单动作 |
| --- | --- |
| 在线 | 离线使用、进入配网、返回 |
| 自动降级 | 立即重试、保持离线、进入配网、返回 |
| 手动离线 | 恢复联网、进入配网、返回 |

菜单优先通过屏幕点选。打开时结束当前云端交互或本地指令窗口，取消其计时器和待处理识别事件；
本地窗口的 8 秒不会暂停后续计，也不会在退出菜单时重新开启。已完成的设备设置不回滚。
菜单打开期间停止唤醒、指令识别及对话收音。执行选项后进入对应模式；选择“返回”则回原模式待机。
只有回到可交互待机且当前没有监听暂停时才恢复唤醒，进入配网仍保持停止识别；
不恢复旧会话、旧窗口或菜单打开前的暂停状态快照。

菜单内双击 BOOT 仍切换“监听暂停”选择，但即使选择恢复监听，也要等菜单关闭并回到可交互待机后才恢复唤醒。
菜单是主动亮屏入口，退出后保持亮屏，用户可用原有息屏操作关闭。

普通界面继续使用屏幕双击切换背光；菜单打开时接管触控，点选不能同时触发息屏手势。
保留显式“返回”入口，不把菜单点击解释成云端或离线语音请求。

### 4.4 无触控时的 BOOT 菜单兜底

菜单始终支持 BOOT 操作，不依赖先检测出触控故障。触控初始化失败、读数持续异常或使用中失效时，
仍能进入、选择和退出菜单，不需要重启、清除设置或语音命令。

| 菜单内操作 | 行为 |
| --- | --- |
| 单击 BOOT | 按显示顺序循环选中下一项，不开始收音 |
| 再次长按 BOOT 3 秒 | 执行当前选中项，选择“返回”则关闭菜单 |
| 双击 BOOT | 只切换监听暂停选择，不移动或确认菜单项 |

打开菜单时默认选中“返回”，屏幕显示选中项及操作提示。打开菜单的那次长按及释放不能确认选项，
须完整释放后重新长按才生效。单击、双击、长按互斥；菜单关闭后的尾随按键事件不得开始聆听。
这一规则仅覆盖菜单内操作；菜单外沿用第 4.1、4.2 节的交互。触控点选可直接执行同一菜单动作，
与按键事件统一串行处理，每次选择只执行一次。

## 5. 本地指令交互

采用两阶段识别：“先唤醒，再识别一条固定指令”。

1. 离线待机时说“你好小妹妹”，或单击 BOOT。
2. 播放简短提示音，屏幕显示“请说指令”；静音时不强制出声。
3. 开启最长 8 秒的指令窗口，识别到一条有效指令后立即结束窗口并执行。
4. 通过屏幕文字和简短提示音反馈结果，然后返回离线待机。
5. 超时、说“取消操作”、再次单击 BOOT 或打开网络菜单均取消尚未完成的识别，
   废弃其待处理事件，不产生设备控制动作；打开菜单时保持在菜单，其余情况回到待机。

息屏时仍可语音唤醒和识别，但普通唤醒、调音量、调亮度不自动亮屏；
文字反馈保留在界面，“打开屏幕”“查看设备状态”和主动打开菜单是亮屏入口。
音量为 0 不影响麦克风识别，屏幕可用于确认结果。

一次窗口最多执行一条指令；未知表达不交给云端，不猜测动作，不因未识别而无限延长窗口。
命令窗口关闭后，若未进入菜单、配网、资源更新或监听暂停，则恢复唤醒检测；
这些占用状态结束后再按当前模式及暂停选择恢复，不能因一次识别使设备失去后续响应。
本地命令音频不上传，后台网络恢复也不能把已采集的本地窗口音频转交云端。

第一版固定指令仅在离线状态生效。在线继续沿用现有云端交互，
避免同一句话被本地控制和云端工具重复执行。

## 6. 首版固定词表

| 固定说法 | 动作 | 约束与反馈 |
| --- | --- | --- |
| 打开屏幕 | 按保存的设定亮度亮屏 | 不修改保存的亮度 |
| 关闭屏幕 | 关闭背光 | LCD、触控、唤醒及指令能力继续运行 |
| 音量大一点 | 当前设定音量加 10 | 上限 100；保存设置并反馈实际结果 |
| 音量小一点 | 当前设定音量减 10 | 下限 0；音量为 0 时仍保留语音输入能力 |
| 屏幕亮一点 | 当前设定亮度加 10 | 上限 100；息屏时只保存值，仍保持息屏 |
| 屏幕暗一点 | 当前设定亮度减 10 | 下限 1；息屏时只保存值，仍保持息屏 |
| 查看设备状态 | 亮屏展示设备状态 | 电池粗档、设定音量、亮度、网络状态及离线原因；未知值如实显示 |
| 取消操作 | 关闭当前指令窗口 | 不改变联网模式或监听暂停状态 |

首版按上述固定说法注册，不承诺同义改写、任意数值参数、连续指令或自然语言理解。
“已到最大／最小”属于可反馈的无变化结果，不反复写入相同设置。

音量沿用 `audio/output_volume`，亮度沿用 `display/brightness`，不修改现有键语义。
执行结果须区分设置已保存、硬件已应用、失败或当前不可应用；
不能在仅保存成功时宣称硬件已生效。离线动作与在线工具共用同一设备控制语义。

网络切换统一使用网络菜单，首版不注册配网、联网、重启、升级或清除配置的语音命令。

## 7. 可支持的能力与边界

| 能力 | 首版范围 |
| --- | --- |
| 本地唤醒与固定控制 | 支持第 5、6 节定义的交互；不依赖云端协议初始化或设备已激活 |
| 表情与界面 | 保留本地表情、设备状态、触控和背光控制 |
| 电池状态 | 使用板级缓存，只显示现有粗档或未知，不推断百分比、充电状态或剩余时间 |
| 时钟 | 本次启动已校时后可继续走时；未校时显示 `--:--`，不承诺离线断电保时 |
| 操作反馈 | 屏幕文字及简短本地提示音，尊重静音设置 |
| 暂停监听 | 保留 BOOT 双击暂停／恢复；模式切换、配网退出、网络恢复都不隐式解除暂停 |
| 自由问答、天气、搜索、云端控制 | 需要联网，离线不提供，不伪造成功或回答 |
| 动态语音报时、播报电量 | 首版不包含，后续需另外规划本地声音资源或合成方案 |
| 网络与低电本地提醒 | 沿用现有开关和硬件校准约束，本方案不自动启用 |

模型缺失、资源不兼容或加载失败时，显示“本地语音不可用”，
保留按键、触控、网络菜单和恢复联网入口；此时不能显示“请说指令”或假装已开启识别。
自动降级时后台仍可恢复联网；手动离线时不能因模型失败擅自联网。

### 7.1 离线启动与待下载资源

启动先校验并加载本机已有有效资源；即使保存了 `assets/download_url`，
也不能因等待下载而跳过现有字体、表情和语音模型。手动离线及自动降级期间均不下载资源，
保留待下载请求，不清除请求来绕过加载，也不因该请求强制联网。
如果现有模型无效，使用上述“本地语音不可用”降级流程，界面使用固件内置的基础字体与状态提示。

允许联网且已恢复在线待机后，待下载请求只能在无会话、本地窗口、反馈、菜单的空闲边界开始。
开始前显示资源更新状态、停止识别与相关播放、释放旧模型及映射资源引用，再写入资源分区；
写入期间沿用不可中断阶段的操作保护，不并行使用正在被覆盖的资源。
仅在写入完成、校验通过并重新加载成功后清除请求；结束后回待机，保留当前监听暂停选择。

下载、校验或加载失败时如实提示并保留请求，不在当前恢复周期无限重试。
只有重新校验仍有效的本地资源才可复用；资源分区已被部分覆盖时不能承诺回退旧包，
应使用基础界面并关闭不可用的本地语音，保留 BOOT 菜单联网／配网入口。
本方案不新增双资源分区或断电回滚承诺；资源失效与恢复流程须单独验收。

## 8. 实现边界与分层建议

以下为后续正式设计与实施的约束，不代表已完成改动。

- **应用层**：统一管理模式选择、离线原因、指令窗口、取消及恢复时机。
  经 `Application::SetDeviceState()` 与状态机表达合法转换；联网策略与监听暂停独立建模，
  不把离线全部混入现有 `idle` 状态后依赖协议空指针推断。
- **板级网络层**：提供启动等待、停止配网、手动离线和后台重试能力，
  将目标行为限定到家用变体；核心代码只使用 Board 能力接口，不引用具体板卡类或其 `config.h`。
- **音频层**：在现有 AFE／MultiNet 链路中支持唤醒与指令窗口，
  不另起第二套竞争麦克风的识别流水线；设备播放反馈时验证自触发与回声干扰。
- **动作层**：固定命令映射到受限的本地动作，共用音量／亮度的 checked 结果与边界，
  不通过构造云端 MCP JSON 调用来模拟离线能力。
- **界面层**：增加菜单、离线来源、指令窗口与错误反馈；区分 Wi-Fi 未连接、服务不可用、
  手动离线和监听暂停，不只显示一个笼统的网络图标。菜单统一处理触控与 BOOT 输入，
  接管期间取消旧指令窗口，并抑制尾随输入。
- **资源与配置**：同步维护命令词、动作标识、模型及资源兼容性校验。
  当前资源打包器只接受 `wake` 动作，需与识别端一起扩展；不能只修改资源词表。
  将现有本地资源加载与下载流程拆开，按第 7.1 节处理待下载请求、映射释放与失败降级。
  不手改 `build/`、`managed_components/` 或生成文件来实现功能。
- **持久化**：增加手动离线选择的兼容字段，缺失时默认允许联网；
  不覆盖既有 Wi-Fi、绑定、音量和亮度设置。具体字段名在正式设计中确定。
- **并发与隔离**：回调只投递应用事件或调度任务；主循环和音频任务不等待网络重试。
  结束会话时废弃旧连接／会话的事件、音频和待处理动作，防止取消后又收音或继续播放。
- **恢复证据**：联网恢复判断与声音提醒开关分离，关闭提醒不能关闭必要的模式判断。
  按第 3.1 节分别表达在线待机条件和媒体验证状态；探测会话与用户会话的回调及动作隔离。
  后台重试的配置拉取、激活或连接探测不触发自动固件安装，保持家用变体现有 OTA 策略。

建议按“BOOT 取消与会话隔离 → 离线模式及网络菜单 → 本地词表与动作 → 资源及实机验证”
拆分后续实施批次。本文不授权代码修改、烧录、提交或发布。

## 9. 验收标准

以下均为后续待执行的验收项，复选框不代表本次已测试。

- [ ] AC01：在线待机单击 BOOT 开始聆听；聆听中再次单击取消；此后单击或唤醒仍可使用。
- [ ] AC02：取消或切换模式后，旧建连回调、识别、云端音频和工具动作不能继续影响当前会话。
- [ ] AC03：有配置但网络不可用时，前台连接等待按 15 秒预算结束，本地界面和操作可用，后台重试不阻塞它们。
- [ ] AC04：无 Wi-Fi 配置时可从配网单击退出；重启后保持手动离线，未清除原有设置和设备绑定。
- [ ] AC05：手动离线跨重启保持；Wi-Fi 关闭且无云端音频上传；网络自行恢复不能将其切回在线。
- [ ] AC06：选择恢复联网撤销手动离线选择；失败后继续本地使用并自动重试，重启仍允许联网。
- [ ] AC07：自动降级无需重新配网；后台重试间隔递增且不超过 5 分钟，手动重试立即发起。
- [ ] AC08：Wi-Fi 可用但云服务故障时不自动配网；不以仅有 Wi-Fi 连接宣称语音服务恢复。
- [ ] AC09：恢复在线不打断本地窗口、反馈或菜单，不自动开始收音，不恢复旧会话。
- [ ] AC10：长按 3 秒可打开网络菜单，选项符合当前模式；不额外触发单击、双击或息屏；下载模式行为保持。
- [ ] AC11：说唤醒词或单击 BOOT 开启最多 8 秒本地窗口；每次至多执行一条指令，超时和取消都返回可再次唤醒的待机。
- [ ] AC12：逐项验证全部八种固定说法、正确动作、上下限、重复动作，以及无匹配时不误执行。
- [ ] AC13：息屏可唤醒、开屏；息屏调亮度不亮屏；查看设备状态会亮屏；静音可识别并通过屏幕反馈。
- [ ] AC14：监听暂停时无唤醒和指令识别；单击、菜单退出、网络恢复不解除暂停；双击恢复正常使用。
- [ ] AC15：音量、亮度跨重启保持且兼容旧设置；保存或硬件应用失败时不显示虚假成功。
- [ ] AC16：首次无网络且未激活也能使用本地能力；模型缺失或失败时明确提示，并可用按键和触控恢复联网。
- [ ] AC17：自动降级及手动离线的本地指令窗口音频均不上传，恢复在线后也不补传；首版在线不重复执行本地命令。
- [ ] AC18：电池异常显示未知；未校时显示 `--:--`；不出现虚构电量百分比、充电状态或离线时间。
- [ ] AC19：WebSocket 与未协商 UDP 探测的 MQTT 路径在控制／hello 证据满足后，即使没有媒体成功记录也可恢复在线待机；有探测的 MQTT 路径还须取得有效 PONG。三种路径均不发送 listen/start 或用户音频，不执行探测会话的播放和控制动作。
- [ ] AC20：探测成功后正常关闭临时会话不造成再次降级；本地窗口结束后可恢复在线，下一次用户主动操作才开始真实对话；断网、配置变化或手动离线后的迟到探测结果均被丢弃。
- [ ] AC21：本地窗口开始 3 秒后打开菜单，停留超过 8 秒再返回，不恢复窗口、不执行旧识别事件；菜单期间双击改变的暂停选择在退出后仍有效。
- [ ] AC22：触控从启动即不可用及菜单中途失效两种场景下，均能仅用 BOOT 选择恢复联网、进入配网和返回；首次长按及释放不确认选项，菜单关闭的尾随输入不启动收音。
- [ ] AC23：存在待下载地址且本地资源有效时，手动离线与自动降级启动均加载现有模型、字体和表情，不下载、不清除请求，固定指令可用。
- [ ] AC24：恢复在线后资源更新仅在空闲边界开始，写入期间没有旧模型或映射引用继续被使用；成功重新加载后才清除请求。下载／校验／加载失败以及模拟部分覆盖后，基础界面与 BOOT 菜单仍可操作，失效模型不会用于识别，且无无限重试。

## 10. 验证与交付范围

主机侧验证：状态转换、持久化默认值、模式恢复、指令窗口超时／取消／去重、动作边界、
旧事件隔离及资源词表与动作映射一致性；补充两种传输及 UDP 探测开关下的恢复证据、
菜单取消窗口与 BOOT 兜底、待下载请求与资源加载／失效的场景。
模拟单调时钟和网络事件，避免依赖真实外部服务。

构建验证：运行 `python3 -m unittest discover -s scripts/tests -v`；
按 `scripts/build.py` 构建家用变体及受公共改动影响的代表路径，
检查独立资源包大小及固件／资源兼容性；不得把主机测试当作固件构建结果。

实机验证：实际家用板上的 BOOT 手势互斥、菜单触控、息屏／静音／暂停、重启保留、
网络和服务故障恢复、长时间内存与任务运行情况；逐条验证词表识别、漏识别、误触发、
电视／旁人说话和设备提示音干扰，以及适用的播放打断和 AEC 行为。
识别窗口 8 秒、前台连接预算 15 秒和步长 10 均为已确认的首版参数，尚无实机效果结论。
