## Rev2.0 家用变体

`config.home.json` 提供本地构建变体 `esp32-s3-touch-lcd-1.85c-home`，
使用 Rev2.0 音频硬件配置及现有分区默认值。构建时显式选择该文件。

```sh
python scripts/build.py waveshare/esp32-s3-touch-lcd-1.85c --config config.home.json --name esp32-s3-touch-lcd-1.85c-home --language zh-CN --wake-word wn9_nihaoxiaozhi_tts
```

`CONFIG_WAVESHARE_1_85C_HOME` 在启动版本检查时跳过自动安装固件，包括服务端的
`force=1` 响应。设备继续读取官方服务配置、处理激活并确认当前镜像有效。
显式发起的固件升级仍走现有升级入口。

首次试机前，核对设备实际分区表、当前启动槽、原应用和匹配资源的校验值，
在设备外准备可离线恢复的镜像。将候选写入已核对的非活动应用槽，记录启动槽切换方式。
资源需要更新时单独写入并准备对应的恢复镜像。使用分区级写入保护 NVS 和设备绑定。

连接官方平台前，用受控版本响应验证普通更新、强制更新和无更新三种情况。
检查应用槽写入和固件下载次数、原槽校验值、配置读取与激活流程。
接入官方平台及回退后，分别验证设备沿用原 Wi-Fi 和绑定并完成一次问答。

家用变体的 BOOT 单击在待机时开始聆听，回答中打断并开始新会话，聆听中保持当前状态。
双击结束当前会话并暂停收音和唤醒，再次双击回到可唤醒的待机。
暂停时显示「监听已暂停」，平台语音通知在暂停期间被跳过。
双击窗口以 300 ms 起测，运行时长按阈值为 3 秒且保留为空，启动下载模式沿用硬件行为。
按键释放、操作请求和主任务处理均有时间戳日志，供实机核对响应时间和手势排他性。

屏幕在同一位置两次完整短触后切换背光，单击、滑动、长触不执行操作。
初始双击间隔为 300 ms，两次触点相距不超过 30 px。息屏只关闭背光，
LCD 更新、触控和语音保持运行；再次双击按保存的设定亮度亮屏。
CST816S 当前驱动只提供一个触点，不能据此确认可靠的多指排除。

语音音量范围为 0–100，亮度为 1–100，沿用 `audio/output_volume` 和
`display/brightness`。音量 0 跨重启保持静音；重启恢复亮屏与唤醒。
息屏期间调亮度只更新保存值，仍然保持黑屏。设置工具返回保存与硬件应用状态，
输出设备关闭时保存音量不代表已应用到硬件；失败请求不会反馈成功。

### 电池与状态显示

家用变体从 Rev2.0 的 GPIO8（ADC1 channel 7）读取 BAT_ADC，使用 ADC oneshot 和
曲线校准，按 R2=200 kΩ、R11=100 kΩ 的三倍分压换算。依据为
[V2 原理图](https://files.waveshare.com/wiki/ESP32-S3-Touch-LCD-1.85C/ESP32-S3-Touch-LCD-1.85C_V2.pdf)
与[官方 Arduino V2 电池采样示例](https://docs.waveshare.net/ESP32-S3-Touch-LCD-1.85C/Arduino/#06_analogread)。
原理图默认装配为 R43=0 Ω、R1 不装，分压输入接开关后的 `BAT_OUT`。
需打开机身电池电源开关；USB 供电时设备可以正常运行而该节点仍没有有效电压。
每秒采样，5 个连续有效读数取中位数；越界或读取失败重建窗口，缓存达到 3 秒过期。
初始化或读取不可用显示未知，不代入满电或充电状态。界面和查询共用板级缓存。

初始粗档以 3650 / 3950 mV 分界，迟滞 30 mV，仅供实机调校，不能当作剩余容量、
低电阈值或供电余量。有效读数报告 `unclassified` 和 `one_bar` / `two_bars` /
`three_bars`；未知只报告 `unknown`。不提供百分比、充电状态或充满判断。
这些读数来自电池供电节点，不能单独证明电池已接入。低电声音保持关闭，需完成
配套电池负载、ADC 偏差和安全供电余量测量后另行启用。

圆屏顶栏分两排：上排为独立时钟，下排为电池粗档、Wi-Fi 和音量。
时钟在对话或暂停期间仍显示，未校时显示 `--:--`。默认字体下表情区固定为
160×160；大字体使用较小的固定区域，字幕出现、隐藏及状态变化不缩放表情。
正常待机不显示状态图标，聆听、等待、回答和暂停分别显示麦克风、进度、
扬声器和关闭麦克风图标。其他状态或异常继续显示短文字。
等待回应仅由当前会话新 VAD 发言之后的非空识别结果触发；回答开始、取消、断线或
10 秒展示超时后撤下，不改变协议超时。仅收到 TTS stop 不重新允许旧识别结果触发。
平台 STT 没有轮次标识时，本地轮次可过滤已排队的旧事件与新发言前的旧 STT，
同通道迟到旧 STT 若恰好落在新 VAD 之后仍无法严格归属，不能据此宣称完全隔离。

### 粉衣小女孩和自定义唤醒资源

可选资源源文件与参数位于 [`assets/home-girl/`](assets/home-girl/README.md)。
先按 `config.home.json` 构建固件，再运行 `python scripts/build_home_girl_assets.py`，
生成独立的 `build/home-girl-assets.bin`。它保留默认资源中的中文字体及 glyph
元数据，加入粉衣日系小女孩表情、待机眨眼和中文 MultiNet7 唤醒词“你好小妹妹”。
该资源不会自动并入常规构建；部署须显式选择独立资源文件，常规
`generated_assets.bin` 仍使用构建配置选择的表情及唤醒模型。

这是通用离线命令识别路径，实际误唤醒、漏唤醒、播放打断和暂停恢复需设备验证；
资源索引或屏幕提示不能单独证明识别词已激活，应核对启动命令表并实际唤醒。

### 可选本地提醒

`CONFIG_WAVESHARE_1_85C_HOME_NETWORK_ALERTS` 和
`CONFIG_WAVESHARE_1_85C_HOME_LOW_BATTERY_ALERTS` 默认关闭；标准 `config.home.json`
不会自动开启它们。第一轮硬件验收后可独立开启网络提醒；低电提醒还需要在
`home_battery_calibration.h` 填写完整有效的实测参数并显式启用。
空配置、无效配置或编译开关关闭时，电池继续报告未知／未分类，不发布正常或低电。

配置读取、激活、MQTT 控制连接、会话握手和媒体可达分别保存故障证据。
Wi-Fi 回连、broker 回连及 hello 各自只更新对应阶段。协商 UDP 探测时以当前通道的
有效 PONG 确认媒体；未协商探测及 WebSocket 路径结合新发言、非空识别和实际成功解码的回复。
`network.service_state` 只有所需阶段都有当前正向证据时为 `available`，未确认时为
`unknown`，持续阶段故障为 `unavailable`。运行掉线沿用锁定 Wi-Fi 组件的自动重连，
保留启动连接失败后进入配网的兜底及已保存配置。

本地提示使用容量为一的异步请求，限制输入 64 KiB、声音 10 秒和 2000 包。
接纳请求不等于已经播出；以首次 PCM checked 写成功消费本轮提醒。
取消和超时会停止后续提交，完成回执等待已在途写结果，不能把 12 秒生产截止当作
驱动调用或声学尾音的中止上限。静音保留未播请求，已开始后被打断不重播。
用户主动开始优先收音；仅自然回答结束后的非实时回合间隙可在下一次收音前提示。
低电优先网络，未知采样保留低电事件但暂停播放资格。暂停、息屏及离线不阻止符合条件的
本地低电提醒；结束回执不能解除暂停或恢复旧会话。暂停时网络通知保持状态标签可见。

### 受控 OTA 响应

本机验证可运行 `python scripts/ota_test_server.py --mode new --base-url http://127.0.0.1:8765`。
实机验证时用 `--host` 绑定设备可达的局域网地址，并在 `--base-url` 中指定同一地址。
`new` 提供新版本，`forced` 提供当前版本及数值 `force=1`，`none` 提供当前版本。
设备检查地址使用 `/ota/`，`/stats` 提供检查次数和固件下载次数。
固件下载 URL 仅记录请求并返回 HTTP 410。候选应在三种响应下继续启动，下载次数保持零。

测试服务仅返回版本和时间字段。使用现有设备连接配置，并在测试后恢复临时 OTA 地址设置。
应用、资源、配置及启动记录全部写入并核验后再复位，回退时采用相同顺序。
主机服务验证命令为 `python -m unittest discover -s scripts/tests -p test_ota_test_server.py -v`。
